## Misses are not equal: dangerous vs safe

Of each system's misses on gold-violated claims:
- **baseline_plus (3 misses): 2 are false confirmations** — it marked violated
  claims `holds` (case_01 `a_nulls`, case_12 `s_pattern`). The user ships a
  wrong doc with confidence.
- **agent (3 misses): 0 false confirmations** — all three are calibrated
  abstentions (`check_failed`), each with a known cause (below). The user is
  told "could not verify", never "verified" wrongly.
- The plain baseline also "verified" wine's row count because it "matches the
  known UCI Red Wine Quality dataset size" (`case_03,baseline,w_rows` in the
  per-claim table) — judging from memorized world knowledge while the actual
  file held 1,611 rows.

  Constitution III).
- Recovered-by-rewrite examples: both fresh phantom columns (case_07

## Agent's three gold misses, each with a cause and a v3 fix

1. `case_02/p_phantom` — the gate's exists-fixture filled the phantom column
   with a constant, so a legitimate uniqueness-style check failed the clean
   fixture twice → abstained. **Fix:** unique-valued clean fixture (v3).
2. `case_04/r_countries` — two check drafts tested a proxy instead of the
   exact distinct count and passed the 25-value mutant → vacuous ×2 →
   abstained. The gate correctly refused to trust them. **Fix:** lessons.md
   entry 7 (exact-count checks).
3. `case_01/a_nulls` — the compound sentence split into two claims; the
   violated half scored, but alignment matched the gold span to the abstaining
   sentinel half. **Fix:** lessons.md entry 8 (one claim per compound
   sentence).
