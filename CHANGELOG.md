# Improvement Changelog

One entry per meaningful iteration (SR-001). Every number links to committed
evidence; the same scorer (`eval/score.py`, span-IoU-anchored, deterministic)
runs at every checkpoint. Removed experiments are recorded with their numbers.

---

## v0 — Harness + baselines (T013)

**What:** Eval foundation built *before* any agent code (Gate G1): 8 seeded
corruption operators with gold-by-construction, 6 accurate data cards whose
every claim is proven true of the committed data on each `pytest` run, cases
01–06 generated byte-identically, and the deterministic scorer. Then both
baselines — `baseline` (card + dtypes + first 50 rows, one no-tools call) and
`baseline_plus` (adds full-column summary statistics + top-10 value counts) —
ran on all six cases.

**Result:** baseline **0.419** macro-F1 (6/23 violations caught);
baseline_plus **0.984** (22/23). Evidence: [results/v0.md](results/v0.md),
per-claim detail in [results/v1_per_claim.csv](results/v1_per_claim.csv).

**Failure observed:** the plain baseline confirmed the case_01 no-empty-cells
claim from its 50-row sample while the full file holds 17 injected nulls —
the hallucinated-confirmation failure mode this project exists to kill
(row `case_01,baseline,a_nulls` in the per-claim table).

**Decision:** Gate G2 passed (span-quoting compliance 100% across all 12
baseline runs — natural-prose cards stay). baseline_plus being near-ceiling
told us the 6 easy cases cannot separate execution from summary-reading; the
Phase 4 suite (cases 07–12, incl. the 1M-row hard case) must carry that.

## v1 — Split agent pipeline with full-data execution (T020)

**What:** extractor → per-claim synthesizer → sandboxed executor over the full
file → ledger → verdicts, all no-tools single-purpose model calls under a
deterministic asyncio orchestrator (research R9). Every `holds`/`violated`
verdict must carry an executed check's computed value (FR-004); prose claims
abstain without synthesis; execution failures retry once then abstain as
`execution_error`. Checks run ungated in v1 (`gate_skipped` recorded — the
mutation gate is v2).

**Result:** agent **1.000** macro-F1, **23/23** planted violations caught,
including the phantom columns (via the missing-column contract), both fuzzy
"roughly X%" claims (computed 3.20% vs claimed ~8%; 34.97% vs ~20%), and the
injected-nulls claim both baselines missed. 46.7k tokens / 370s for the sweep
vs 36.1k / 343s for baseline_plus. Evidence: [results/v1.md](results/v1.md),
[results/v1_per_claim.csv](results/v1_per_claim.csv), full ledgers under
`runs/` with message streams in `messages.jsonl`.

**Failures observed and fixed along the way:**

1. **Gold-direction flaw (eval bug, ours not the agent's).** The first draft
   of case_04's stale-coverage corruption *widened* the claimed date window
   ("1 to 24 December" over data ending the 21st) — a literally-true
   containment claim the agent rightly judged `holds` against a `violated`
   gold. Lesson: **coverage claims must be corrupted in the falsifiable
   direction.** Fixed in commit `00708c0` (window narrowed to "5 and 21
   December"; data starts the 1st), case regenerated, all systems re-run.
2. **SDK turn-cap fragility.** `max_turns=1` intermittently surfaced as a
   fatal `ResultError` that killed a whole case. Fixed in `45a5a0c`: turn-cap
   results with delivered text count as success, transient transport failures
   burn a retry attempt instead of aborting, and a single claim's hard failure
   degrades to `unverifiable(check_failed)` rather than killing the case.
3. **Agent false alarms on extra claims** (not gold, no F1 impact, but audit
   noise): it invented a country-of-station check from NOAA station-name
   strings and judged a true statement violated, and read retail's "each row
   is one product line" hyper-literally. Queued for the v3 lessons/abstention
   pass.

**Decision:** kept. v1 saturates the easy suite, so its value over
baseline_plus rests on (a) the one claim class only execution settles and
(b) audit quality (computed values + evidence rows per verdict). v2 must
(i) measure the vacuous-check rate the ungated v1 cannot see, and (ii) run the
full 12-case suite where summary statistics provably fail (rare category after
row ~810k).
